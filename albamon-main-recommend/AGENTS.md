# 프로젝트: 알바몬 메인 추천 사유 프로토타입

## 적용 범위

- 이 지침은 `albamon-main-recommend/` 프로젝트에만 적용한다.
- 위치 동의 비교 프로토타입(`albamon-onboarding-consent/`)의 완료 화면(메인)·공고뷰·정책 패널을 복제해 만들었다(2026-11-09). 두 폴더를 함께 고치지 않는다.
  - 빼낸 것: 로그인·온보딩 STEP 전부, 위치 동의 시트·OS 권한 팝업, 카카오맵, 수정 전/후 전환, 코치마크·스크롤 안내 토스트, 기록(`ut.log`)
- 잡코리아 콘텐츠LAB의 JAMS 2.0 규칙을 자동으로 가져오지 않는다.

## 정책서

- PO 정책서 FigJam `Season3_메인 추천사유 표기`(VyRiJZLODsNWO1HSEkIkqC, 3165:7694).
- 추천 사유는 추천 엔진이 준 일반 공고에만 붙인다. CPC/CPT 광고 공고에는 붙이지 않는다. 스크랩·클릭·이력서 풀 출처 공고에도 붙이지 않는다.
- 정책서 표의 Extreme 라벨(`{키워드}연관`, 키워드 3글자 말줄임)은 예전 기준이다. B1 문구의 키워드 길이 규칙은 아직 정해지지 않았다(Figma는 `바리스타` 4글자를 그대로 보여준다).

## 흐름과 데이터

- 온보딩 없이 메인부터 연다. 코치마크는 띄우지 않는다(사용자 결정: 실험 대상은 검색·지원 이력이 있는 기존 회원).
- 데모 사용자: 김모니. 최근 `바리스타` 검색, 카페 알바 지원. 메인 조건은 원본 기본값(서초구 10km · 바리스타 외 2)과 같다.
- 공고 30개는 `jobs.js`에 고정해 둔다(원본처럼 카카오로 동 이름을 받지 않는다). 스크롤 길이감을 보려고 30개로 늘렸다(사용자 요청 2026-11-10). 1번 카드는 Figma 혼합 Test 카드와 같다.
- 사유 분포(사용자 결정 '섞어서', 15개마다 검색 3·지원 3·광고 2 비율 유지): 검색 1·6·11·16·21·27, 지원 2·8·13·18·23·29, 광고 4·9·19·25, 나머지는 사유 없음. 첫 화면에 검색·지원이 하나씩 보인다.
- 검색 사유 카드는 바리스타 공고, 지원 사유 카드는 카페·베이커리 공고로 맞춘다.
- 급여는 모두 시급이다. 정책서의 `그 외 급여 유형 n,nnn만원` 규칙은 구현하지 않았으므로 월급·일급 공고를 넣을 때는 표기를 함께 고친다.
- 공고 카드를 누르면 공고뷰가 밀려 들어온다. 스크랩·지역·검색·퀵메뉴·필터·탭바·`지원하기`는 동작하지 않는다.

## 프로젝트 구성

- `index.html`: 메인, 공고뷰, 정책 패널 문구
- `style.css`: 토큰, 폰 프레임, 반응형
- `home.css` / `home.js`: 메인과 공고 카드(추천 사유 포함)
- `jobs.js`: 더미 공고와 추천 사유, 공고뷰 값
- `detail.css` / `detail.js`: 공고뷰
- `app.js`: 화면 밀어서 뒤로 가기(공고뷰만 기록을 쌓는다), 모바일 viewport 높이. `window.mainNav`
- `policy.js` / `policy.css`: 화면별 정책 패널(PC 900px 이상에서만 폰 오른쪽). 공고뷰가 열리면 `공고뷰` 항목을, 아니면 `메인` 항목을 펼친다.

## 화면별 정책 패널

- 공개 페이지라 실험 수치와 Figma·FigJam 링크는 넣지 않는다.
- 프로토타입에 없는 정책에는 `프로토타입 미구현` 태그를 붙인다: 스크랩 동작, 읽음 표시.
- 시안이나 정책이 바뀌면 패널 문구와 머리말 날짜(`pol-meta`)를 같이 고친다.

## 작업 규칙

- 기존 텍스트와 시안 의미를 요청 없이 바꾸지 않는다.
- 반복되는 색상과 규격은 CSS 변수로 관리한다.
- 에셋은 Figma에서 받은 파일을 그대로 쓴다.
- 사용자는 file://로 연다. CSS mask, fetch처럼 file://에서 막히는 기능은 쓰지 않고, 검수도 file://로 한다.
- GitHub Pages는 파일을 10분간 캐시한다. CSS·JS를 고쳐 배포할 때는 `index.html`의 `?v=` 값을 함께 올린다.
