# 프로젝트: 알바몬 온보딩 (탐색구조 Track)

## 적용 범위

- 이 지침은 `albamon-onboarding/` 프로젝트에만 적용한다.
- 잡코리아 콘텐츠LAB의 JAMS 2.0 규칙을 자동으로 가져오지 않는다.

## 프로젝트 구성

- `index.html`: 화면 구조(로그인, STEP 0, STEP 1-1 지역 목록, STEP 1-2 내 근처, STEP 2·3, 완료 화면), 위치 동의 시트
- `style.css`: 토큰, 화면 스타일, 반응형 처리
- `app.js`: 지역 데이터, 선택 규칙, 화면 전환. `window.onboarding`으로 상태·화면 전환을 `home.js`·`nearby.js`에 공유한다. UT 프로젝트와 같은 파일이다(UT 전용 기록 `ut.js`가 없으면 기록 없이 동작).
- `nearby.css` / `nearby.js`: STEP 0, 위치 동의(실제 브라우저 위치 권한), STEP 1-2 내 근처(카카오맵 지도·주소 검색). UT 프로젝트와 같은 파일이다.
- `home.css` / `home.js`: 온보딩 완료(홈) 화면, 완료 연출 시안 A·B·C·D, 시안 비교 UI
- `assets/`: Figma에서 내려받은 SVG·이미지 (`assets/home/`은 홈 화면 전용, `assets/ut/`는 STEP 0·내 근처 화면)
- 순수 HTML/CSS/JavaScript로 구현한다. 기본 폰트는 Pretendard다.

## 화면 기준

- PC에서는 390×844 디자인을 휴대폰 프레임 형태로 보여준다.
- 모바일(`max-width: 520px`)에서는 프레임을 없애고 화면 전체를 쓴다. 목업 상태바와 키보드 이미지는 숨긴다.
- PC와 모바일은 각각 따로 검수한다.

## 상호작용 규칙

- 로그인(모든 버튼·X) → STEP 0 → `지역 선택하기`(STEP 1-1 목록) 또는 `내 근처 선택하기`(위치 동의 → STEP 1-2 지도). 동의하지 않거나 권한이 없으면 기본 위치는 시청역이다.
- STEP 1-2: 지도를 첫 화면에서 바로 끌어서 움직이고, 검색창을 누르면 같은 화면에서 타이틀이 펼쳐지며 검색 결과가 지도 자리에 나온다. 결과를 고르면 지도로 돌아와 그 위치로 옮긴다. 세부 규칙은 UT 프로젝트 CLAUDE.md의 '카카오맵' 항목과 같다.
- 카카오맵·위치 권한은 file://에서 동작하지 않는다. 내 근처 화면은 `python3 -m http.server 8765`(vibe-coding-lab 루트)로 띄워 `http://localhost:8765/albamon-onboarding/`에서 확인한다(카카오 앱 등록 도메인).
- 화면 밀어서 뒤로 가기: 위치 동의 시트·STEP 1-2 검색·STEP 2·3에서만 앞 화면으로 돌아간다(app.js 기록 스택).
- STEP 1: 최대 10곳 선택, 초과 시 토스트. 같은 시·도의 `전체`와 개별 시·군·구는 함께 담지 않는다.
- STEP 1: `재택 포함` 체크박스만 둔다(툴팁·안내 아이콘은 제거됨). 지역·재택 선택값은 온보딩이 끝날 때까지 STEP 2·3을 오가도 유지한다.
- STEP 2: 처음 선택하면 바로 STEP 3으로 넘어간다. STEP 3에서 돌아오면 선택 상태와 `다음` 버튼을 보여주고, 다른 기간을 누르면 바로 STEP 3으로 이동한다.
- STEP 3: `한 달 이내`는 단기 업직종 7개, 그 외는 장기 업직종 10개를 보여준다. 같은 카테고리로 다시 들어오면 선택값을 유지하고, 다른 카테고리면 새로 고른다.
- STEP 3 `공고 보기` → 온보딩 완료(홈). 홈의 조건 표시는 다음 규칙을 따른다.
  - 상단 위치: STEP 1 첫 선택지 기준 `○○구 10km`(전체 선택이면 시·도명). 내 근처면 `○○동 {반경}km`(기본 위치면 `시청역 {반경}km`). D 팝업 배지도 같은 이름을 쓴다.
  - 하는 일 칩: 첫 선택 업직종 + `외 N` (미선택 문구는 `하는 일`)
  - 기간 칩: `한 달 이내`·`한 달 이상`만 선택 상태, `상관 없어요`는 미선택 `일하는 기간`
  - `일하는 요일` 칩은 미선택 상태로 둔다(시안의 `주말` 대체).

## 온보딩 완료 시안 비교

- 디자인 시스템 반영본: Figma 섹션 `온보딩 완료 -> 전체적으로 애니메이션 적용 필요`(4598:280964)
- 호칭(2026-10-22 재정리): 남은 시안은 A~D, 소거한 시안은 `드랍했던 버전 A안/B안`으로 부른다. 링크 값은 `a`~`d`, `drop-a`, `drop-b`.
- A 코치마크: Figma 그대로. 딤 30% → 1/2 상단 지역(흰 하이라이트 r14, 말풍선 `다음`·`건너뛰기`) → 2/2 필터 바(x10·w365·h64·r16, `홈에서 알바찾기`). 마지막 버튼을 누르면 필터 바가 고정되는 위치까지 스크롤된다.
- B 하이라이트: 지역·칩을 동시에 3번 반짝임(자체 연출) + DS 토스트 `선택한 조건을 적용했어요`(주황 체크 아이콘).
- C 스크롤 힌트: 화면을 120px 살짝 올렸다 내리며 DS 토스트 `내려서 맞춤 공고 더 보기 ⌄`를 띄운다. 토스트를 누르면 필터 고정 위치까지 스크롤, 직접 스크롤하면 사라진다. 사용자가 먼저 스크롤하면 넛지·토스트 생략.
- D 팝업: 홈 위 모달(AM_모달 기본_one button). 조건 배지(지역 전체 이름 → 기간 → 하는 일)는 넘치면 자동으로 가로로 흐른다. `새로워진 홈에서 알바보기` → 필터 고정 위치까지 스크롤, `×`는 닫기만.
- 드랍했던 버전 A안(조건 착지)·B안(공고 영역 로딩)은 전환 탭에서만 빠지고 `?v=drop-a`, `?v=drop-b`로 볼 수 있다.
- 시안 전환·다시 보기·처음부터는 완료 화면에서만 보인다(PC 상단 바, 모바일 좌하단 런처 → 시트). `처음부터`는 온보딩 상태를 비우고 로그인으로 돌아간다.
- 링크에 시안을 지정하지 않으면 남아 있는 첫 시안(A)으로 시작한다. `index.html?done&v=b`처럼 열면 기본 조건(서초구 · 한 달 이상 · 카페 외 2)으로 해당 시안이 바로 열린다.
- 필터 고정 스크롤 위치 = 추천 섹션 위치 + 필터 바 위치 − 헤더 높이. 고정 상태 배경은 64px(칩 행 48 + 16)로 고정한다.
- 필터 칩 행은 가로 스크롤 영역이라 아래로 넘치는 하이라이트가 잘린다. 아래 여백 14px + 음수 마진으로 공간을 확보해 둔다.

## 작업 규칙

- 기존 텍스트와 시안 의미를 요청 없이 바꾸지 않는다.
- 반복되는 색상과 규격은 CSS 변수로 관리한다.
- 에셋은 Figma에서 받은 파일을 그대로 쓴다. 업직종 선택 아이콘(`job-*-on.svg`)은 Figma 원본 5개와, 시안에 선택 상태가 없는 8개는 기본 아이콘의 색(#C0C7CD)만 #FF6D12로 바꿔 만들었다(원본 5개와 같은 방식).
- HTML 파일을 직접 열어(file://) 확인하므로 CSS mask, fetch처럼 file://에서 막히는 기능은 쓰지 않는다. 단, 지도(카카오맵)는 http(s)에서만 보인다.
- 앞단(app.js·nearby.js·nearby.css·style.css·assets/ut)을 고칠 때는 UT 프로젝트와 같은 내용인지 함께 확인한다.
- GitHub Pages는 파일을 10분간 캐시한다. `style.css`·`app.js`를 고쳐 배포할 때는 `index.html`의 `?v=` 값을 함께 올려 새 HTML과 옛 JS가 섞이지 않게 한다.
