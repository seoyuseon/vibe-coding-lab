# 프로젝트: 알바몬 온보딩 위치 동의 플로우 비교 프로토타입

## 적용 범위

- 이 지침은 `albamon-onboarding-consent/` 프로젝트에만 적용한다.
- UT 프로젝트(`albamon-onboarding-ut/`)를 복제해 만들었다(2026-11-04). 두 폴더를 함께 고치지 않는다.
  - 빼낸 것: 기록(`ut.js`·Firebase), 진행자 메뉴, 대시보드, 과제 종료 팝업, 완료 화면 B 하이라이트
- 잡코리아 콘텐츠LAB의 JAMS 2.0 규칙을 자동으로 가져오지 않는다.

## 흐름

로그인(모든 버튼·X) → STEP 0 → 둘 중 하나
- `지역 선택하기`(수정 전) / `지역 직접 고르기`(수정 후) → STEP 1-1 지역 목록
- `내 근처 선택하기`(수정 전) / `내 주변에서 찾기`(수정 후)
  - 수정 전: 위치 동의 시트 → `동의할게요` → OS 권한 팝업(시트 위) / `다음에` → 기본 위치(시청역)
  - 수정 후: 바로 OS 권한 팝업. 누른 것으로 이용약관 동의를 대신한다(`state.consent = true`).
  - OS 권한: `한 번 허용`·`앱을 사용하는 동안 허용` → 데모 위치 / `허용 안 함` → 기본 위치(시청역)
→ STEP 1-2 → STEP 2 근무기간 → STEP 3 하는 일 → 완료 화면(A)
- STEP 1-1·STEP 1-2 하단 `이전`(TO-BE 5200:180321 · 5200:180453)은 STEP 0으로 돌아간다. 고른 지역은 그대로 남는다. 수정 전에서 이미 동의한 뒤 다시 `내 근처 선택하기`를 누르면 동의 시트 없이 OS 팝업만 뜬다.

- OS 권한 팝업은 실제 브라우저 권한 대신 Figma 목업을 매번 띄운다. 몇 번을 다시 봐도 같은 흐름이 나오고, 회의에서 화면을 공유해도 실제 위치가 나오지 않는다.
- 데모 위치: `서울 서초구 서초대로 301`(37.494331, 127.014509, 카카오 주소 검색값). Figma STEP 1-2 디폴트 검색창·OS 팝업 지도(교대역)와 같은 곳이다. 완료 화면 위치는 `서초동 {반경}km`.
- 현재 위치 버튼: 서비스 동의가 없으면(수정 전 `다음에`) 동의 시트부터, 권한을 허용했으면 바로 데모 위치로, 아니면 OS 팝업을 다시 띄운다.
- `위치기반서비스 이용약관`(수정 후)과 `이용약관 보기`(수정 전 시트)는 눌러도 아무 동작이 없다.

## 수정 전/후 전환 (`compare.js` · `compare.css`)

- 링크로 고른다: `?ver=before` | `?ver=after`(지정이 없으면 수정 후). `body[data-ver]`로 STEP 0 두 화면 중 하나만 보인다.
- PC: 폰 위 막대에 `수정 전 | 수정 후`와 `처음부터`. 늘 보인다.
- 모바일(`max-width: 520px`): 떠 있는 버튼(`전`/`후`) → 바텀시트. 로그인·STEP 0에서는 오른쪽 위, 완료 화면에서는 탭바 위 왼쪽에 뜨고 나머지 화면에서는 숨긴다.
- 버전을 바꾸면 STEP 0부터 다시 시작한다(로그인 화면이면 그대로 둔다). `처음부터`는 로그인으로 돌아간다.

## 프로젝트 구성

- `index.html`: 화면 구조(로그인, STEP 0 수정 전·후, STEP 1-1, STEP 1-2, STEP 2·3, 완료 화면), 공고뷰, 위치 동의 시트, OS 권한 팝업, 전/후 전환 UI
- `style.css`: 토큰, 기존 화면 스타일, 반응형 처리
- `nearby.css` / `nearby.js`: STEP 0, 위치 동의 시트·OS 권한 팝업, STEP 1-2 내 근처(카카오맵 지도·검색)
- `home.css` / `home.js`: 완료 화면과 A 코치마크 연출
- `jobs.js`: 완료 화면 더미 공고. `detail.css` / `detail.js`: 공고뷰(`지원하기`는 동작 없음)
- `app.js`: 지역 데이터, 선택 규칙, 화면 전환. `window.onboarding`으로 상태를 공유한다.
- `compare.js` / `compare.css`: 수정 전/후 전환
- `policy.js` / `policy.css`: 화면별 정책 패널(PC 전용). 문구는 `index.html`의 `<aside class="policy">`에 있다.
- `assets/consent/`: TO-BE에서 받은 에셋. `os-popup.jpg`는 Figma 이미지(1206×2622 iOS 캡처)를 팝업 영역만 잘라 2배(524×898)로 줄였다.
- `ut.log` 호출은 UT에서 넘어온 그대로 남아 있고, `ut.js`가 없어 아무것도 기록하지 않는다.

## 화면별 정책 패널 (`policy.js` · `policy.css`)

- PC(가로 900px 이상)에서만 폰 오른쪽에 둔다. 모바일과 좁은 화면에서는 숨긴다.
- 화면마다 접히는 항목 하나다. 지금 화면의 항목을 펼치고, OS 권한 팝업이 떠 있으면 그 항목을 펼친다. STEP 0에서는 지금 보는 버전(수정 전/후) 박스를 강조한다.
- 기준은 Figma TO-BE(가이드·주석)다. PO 온보딩 정책서(FigJam `[26.12.03] 온보딩 개선`)는 TO-BE에 없는 내용만 옮긴다.
  - 정책서의 위치 동의(모달 동의) 내용은 예전 기준이라 쓰지 않는다.
  - 업직종 이름은 Figma, 소분류는 정책서 표를 쓴다.
- 프로토타입에 없는 정책에는 `프로토타입 미구현` 태그를 붙인다: 온보딩 없이 가는 분기(기존·기업 회원, 광고 유입, 재설치 아님), 채용관 공통 검색조건 동기화, 코치마크 1회, 중간 이탈 저장·재진입, 저장값 없을 때 서울 기본값.
- 공개 페이지라 실험 수치(할당·유의수준 등)와 Figma·FigJam 링크는 넣지 않는다. 개요에는 AS-IS와의 비교가 실험(구 온보딩 vs 신규 온보딩)이라는 것만 적는다.
- 시안이나 정책이 바뀌면 패널 문구와 머리말 날짜(`pol-meta`)를 같이 고친다.

## 카카오맵

- 카카오 개발자 앱 `온보딩 UT`의 JavaScript 키를 `nearby.js`에 둔다. JavaScript 키는 공개용이다. REST·Admin 키는 코드에 넣지 않는다.
- 등록 도메인: `https://seoyuseon.github.io`, `http://localhost:8765`. 다른 주소에서는 지도가 뜨지 않는다.
- file://에서는 카카오맵이 동작하지 않는다. 지도 자리에 안내 문구만 보인다. 지도 화면은 `python3 -m http.server 8765`(vibe-coding-lab 루트) 또는 배포 주소에서 확인한다.
- STEP 1-2 지도·검색 상태, 반경 원과 안내 문구, 완료 화면 위치 표기는 UT 프로젝트 CLAUDE.md의 '카카오맵' 항목과 같다.

## 화면 밀어서 뒤로 가기

- 뒤로 갈 수 있는 상태에서만 브라우저 기록을 쌓는다(app.js `navPush`/`navPop`): 위치 동의 시트, STEP 1-2 검색 상태, 공고뷰, STEP 2·3.
- OS 권한 팝업이 떠 있는 동안 동의 시트는 밀어도 닫히지 않는다.

## 작업 규칙

- 기존 텍스트와 시안 의미를 요청 없이 바꾸지 않는다.
- 반복되는 색상과 규격은 CSS 변수로 관리한다.
- 에셋은 Figma에서 받은 파일을 그대로 쓴다.
- 지도 외 화면은 file://로도 확인할 수 있어야 한다. CSS mask, fetch처럼 file://에서 막히는 기능은 쓰지 않는다.
- GitHub Pages는 파일을 10분간 캐시한다. CSS·JS를 고쳐 배포할 때는 `index.html`의 `?v=` 값을 함께 올린다.
