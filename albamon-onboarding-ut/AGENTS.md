# 프로젝트: 알바몬 온보딩 UT 프로토타입

## 적용 범위

- 이 지침은 `albamon-onboarding-ut/` 프로젝트에만 적용한다.
- `albamon-onboarding/`(시안 비교용)를 복제해 UT 전용으로 다듬은 별도 프로젝트다. 두 폴더를 함께 고치지 않는다.
- 잡코리아 콘텐츠LAB의 JAMS 2.0 규칙을 자동으로 가져오지 않는다.

## 디자인 원본

- Figma: https://www.figma.com/design/VZmtSaO9fKCxIDtOq5Tx1x/-탐색구조-Track--handoff?node-id=4607-317686
- 섹션 `20261022 또또 수정 중`(4607:317686)이 UT 확정본이다.
- 완료 화면은 섹션 `온보딩 완료 -> 전체적으로 애니메이션 적용 필요`(4598:280964)의 A 코치마크 · B 하이라이트만 쓴다.

## 흐름

로그인(모든 버튼·X) → STEP 0 도입부 → 둘 중 하나
- `지역 선택하기` → STEP 1-1 지역 목록(기존 STEP 1)
- `내 근처 선택하기` → 위치 동의 시트
  - `동의할게요` → 실제 브라우저 위치 권한 요청 → 허용이면 현재 위치, 거부·실패면 기본 위치(서울 서초구 서초대로 301)로 STEP 1-2
  - `다음에` → STEP 1-2(기본 위치) 위에 `알바 탐색위치` 시트를 바로 연다(Figma 연결선 기준)
→ STEP 2 근무기간 → STEP 3 하는 일 → 완료 화면(그룹 A 또는 B)

- STEP 2 `이전`은 STEP 0에서 고른 방식(지역 목록 / 내 근처)으로 돌아간다.
- 법무 검토에 따라 위치는 서비스 안 동의 + 브라우저 권한, 두 번 묻는다. Figma의 OS 팝업 목업은 실제 브라우저 권한 창으로 대신한다.

## 프로젝트 구성

- `index.html`: 화면 구조(로그인, STEP 0, STEP 1-1, STEP 1-2, STEP 2·3, 완료 화면), 바텀시트 3개, 진행자 메뉴
- `style.css`: 토큰, 기존 화면 스타일, 반응형 처리
- `nearby.css` / `nearby.js`: STEP 0, STEP 1-2 내 근처, 위치 동의, 알바 탐색위치 시트, 주소검색(카카오맵)
- `home.css` / `home.js`: 완료 화면과 A·B 연출, 완료 화면 행동 기록
- `jobs.js`: 완료 화면 더미 공고(하는 일 13종 × 실제 브랜드 공고 묶음, 재택 공고)와 목록 만들기, 공고뷰용 상세 값
- `detail.css` / `detail.js`: 공고뷰(채용정보)와 과제 종료 팝업
- `assets/detail/`: 공고뷰 에셋(Figma 4685:372142)
- `app.js`: 지역 데이터, 선택 규칙, 화면 전환. `window.onboarding`으로 상태를 공유하고, 화면이 바뀔 때 `onboarding:screen` 이벤트를 보낸다.
- `ut.js` / `ut.css`: 세션·기록(Firebase), 진행자 메뉴
- `dashboard.html`: 결과 대시보드(실시간)
- `assets/ut/`: UT 섹션에서 새로 받은 에셋, `assets/home/`: 완료 화면 에셋

## 카카오맵

- 카카오 개발자 앱 `온보딩 UT`의 JavaScript 키를 `nearby.js`에 둔다. JavaScript 키는 공개용이다. REST·Admin 키는 코드에 넣지 않는다.
- 등록 도메인: `https://seoyuseon.github.io`, `http://localhost:8765`. 다른 주소에서는 지도가 뜨지 않는다.
- file://에서는 카카오맵과 위치 권한이 동작하지 않는다. 지도 자리에 안내 문구만 보인다. 지도 화면은 `python3 -m http.server 8765`(vibe-coding-lab 루트) 또는 배포 주소에서 확인한다.
- STEP 1-2 미리보기 지도는 직접 움직이지 않고, 누르면 `알바 탐색위치` 시트가 열린다(Figma 연결: img_map → 지도 위치 변경).
- 반경 원은 실제 반경(1·3·7·10km)으로 그리고, 원이 카드에 들어오는 축척으로 맞춘다. 안내 문구: 1km 걸어서 15분 · 3km 뛰어서 30분 · 7km 자전거 20분 · 10km 자전거 30분.
- 카카오가 돌려주는 `서울특별시` 같은 시·도 이름은 시안 표기(`서울`)로 줄여 보여준다.
- 완료 화면 상단 위치: 지역 목록은 `○○구 10km`, 내 근처는 `○○동 {반경}km`.

## 완료 화면 공고 (더미)

- 내부 UT라 실제 브랜드 이름을 쓴다(사용자 확인). 전시장·테마파크처럼 근무지가 고정된 곳은 고른 지역과 어긋나 보이므로 회사 이름에 장소를 넣지 않는다.
- 고른 하는 일을 번갈아 섞어 20개 안팎을 보여준다. 지점이 없는 업종은 회사명을 여러 개 두고 돌려 쓰고, 그래도 모자라면 기간이 다른 공고를 고른 기간으로 바꿔 채운다(월급 공고는 제외). 하는 일을 하나만 고르면 업종에 따라 9~19개다. 기간이 한 달 이내면 1일·1주일이하·1주일~1개월 공고, 한 달 이상이면 그 외, 상관없으면 전부에서 고른다.
- 재택 포함이면 재택 공고 2개를 3·8번째에 끼운다(근무지 `재택근무`).
- 근무지 동 이름은 카카오 주소 변환으로 받는다. 내 근처는 반경 안, 지역 선택은 고른 구 안(여러 구면 번갈아). STEP 2에 들어올 때 미리 받아 둔다. file://에서는 `서울 서초구`처럼 구까지만 보인다.
- 프랜차이즈는 동 이름으로 지점명을 붙인다(서초동 → `스타벅스 서초`, 제목 `스타벅스 서초점 …`).
- 같은 조건이면 늘 같은 목록이 나온다(조건으로 만든 시드). 그래서 A/B는 내용이 같고 연출만 다르다.

## 공고뷰 · 과제 종료

- 공고뷰는 Figma `공고뷰 참고 1`(4685:372142)에서 헤더, 상단정보(등록일·제목·마감·해시태그·신뢰 칩), 근무조건, 모집조건, 근무지역(주소·지도 띠), 하단 `지원하기`만 가져왔다. 상세요강은 원본이 이미지라 짧은 텍스트로 대신했다. 지원방법·채용담당자·기업정보·추천 공고는 넣지 않았다.
- 공고 카드를 누르면 홈 위로 공고뷰가 밀려 들어오고, 뒤로 가면 보던 목록 위치로 돌아간다. 카드 안 별(스크랩)은 기록만 한다.
- 과제 종료 팝업(`과제가 끝났어요`): 공고뷰의 `지원하기`, 또는 홈에서 공고가 아닌 이동 지점(상단 지역·메뉴·검색·퀵메뉴·필터·탭바, 홈 탭 제외)을 누르면 뜬다. `확인`을 누르면 닫히고 그 화면에 머문다.
- 공고뷰의 캡처·스크랩함·공유·주소 복사·지도 보기는 기록만 한다.

## 진행자 메뉴 · 기록

- 화면 왼쪽 위를 1.5초 길게 누르면 열린다(PC: Option/Alt + M, 또는 링크에 `?mod`).
- 참가자 번호를 정하고 `새 세션 시작 · 처음부터`를 눌러야 기록된다. 세션이 없으면 아무것도 기록하지 않는다.
- 그룹은 홀수 A(코치마크), 짝수 B(하이라이트)가 기본이고 바꿀 수 있다. `연습 세션`은 대시보드 집계에서 빠진다.
- STEP 0 버튼 순서(지역 선택하기 위 / 내 근처 선택하기 위)도 참가자마다 정한다. 기본은 P1 기본 · P2·P3 반대 · P4·P5 기본 · P6 반대(6명이면 3:3). 세션 없이 볼 때는 링크에 `?order=nearby`.
- 기록은 localStorage 대기열에 먼저 쌓고 Firestore(`contents-home-ut` 프로젝트)의 `onboarding_ut_sessions`, `onboarding_ut_events`에 묶어서 보낸다. 오프라인·새로고침에도 남아 있다가 다시 보낸다.
- 참가자를 바꾸기 전에 iPhone의 Safari 위치 권한을 `묻기`로 되돌린다. 진행자 메뉴에 현재 권한 상태가 보인다.
- `완료 화면 미리보기`·`index.html?done&v=a|b`는 기록하지 않는다.

## 테스트폰 (iPhone 15)

- 393×852. Safari에서 `홈 화면에 추가`로 열면 주소창 없이 앱처럼 보이고, 화면을 밀어 뒤로 가는 문제도 없다.
- Safari 브라우저로 열어도 동작한다. 화면 높이가 낮으면 STEP 1-2 지도 카드가 세로로 줄어든다.
- 브라우저 뒤로 가기는 막고 `browser_back`으로 기록한다.

## 작업 규칙

- 기존 텍스트와 시안 의미를 요청 없이 바꾸지 않는다.
- 반복되는 색상과 규격은 CSS 변수로 관리한다.
- 에셋은 Figma에서 받은 파일을 그대로 쓴다.
- 지도 외 화면은 file://로도 확인할 수 있어야 한다. CSS mask, fetch처럼 file://에서 막히는 기능은 쓰지 않는다.
- GitHub Pages는 파일을 10분간 캐시한다. CSS·JS를 고쳐 배포할 때는 `index.html`의 `?v=` 값을 함께 올린다.
